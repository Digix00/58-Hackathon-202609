# インクルーシブな推薦

## 目的と利用条件

身近な悩みを入口に、普段読まない声へ関心を広げ、届く機会の少ない投稿にも接点を作る。LINEログイン済みLIFFで `sort=recommended` を使い、通常Web・未ログインは新着順とする。

## 候補と順位

公開済みで自分以外の投稿を、新着順で表示件数の5倍（最大250件、通常20件に対して100件）取得する。指定された性別・都道府県・クラスタの絞り込みを守る。前ページの未返却候補を復元し、足りないときだけ次の候補群を追加する。

候補から一件ずつ、次の順序で選ぶ。

1. 直前と異なるクラスタがあれば、その候補を使う。未分類同士を同じクラスタとは扱わない。
2. その中に未読があれば未読だけを使う。分類済みと未分類で優先度を変えない。
3. 以下の3枠を繰り返す。

| 枠 | 選定 | 同条件の優先順 |
| --- | --- | --- |
| 身近なテーマ | 直近50件の公開投稿の閲覧履歴にあるクラスタ | 新着、ID降順 |
| 未知のテーマ | その履歴にないクラスタ、または未分類 | 新着、ID降順 |
| 届く機会 | 実際の閲覧者数が少ない投稿 | 古い投稿、ID降順 |

身近・未知の候補がない場合は、その時点の候補から新着順で補う。履歴なし・全件既読・単一クラスタでも、候補を重複なく最後まで返す。同じクラスタの連続回避が優先するため、別クラスタの既読投稿が未読より先になる場合がある。

年代・性別・地域の入力有無、本人の属性との一致、リアクション数で加減点しない。属性を使った順位付け・センシティブ属性の推測は行わない。クラスタ未生成・処理失敗でも原文を候補に含める（クラスタ指定の絞り込みを除く）。

## 閲覧機会の計測

既存の投稿表示時の既読APIと `concern_views` を使う。ログイン済み利用者がフィードの表紙を開いて本文を表示したとき、または詳細を表示したときに記録する。一人一投稿一回で、投稿者自身を集計から除く。APIの先読みや `feed_impressions` の件数は順位に使わない。

これは「本文が表示された利用者数」であり、読了・理解・滞在時間を示さない。未ログイン閲覧は数えない。通信失敗で既読記録が届かない場合もある。公開レスポンスに人数を出さず、新しい個人情報を保存しない。

## ページングと失敗時

アルゴリズムはv3、推薦cursorはv7。次の枠 `nextSlot`（0〜2）、最後のクラスタ、未返却候補、取得位置を保持する。表示件数が1や20でも次ページから続きを選び、フォールバックで返した件数も枠を進める。次ページでは閲覧状態・閲覧者数を再取得する。旧バージョン・不正な枠のcursorは400 `INVALID_CURSOR` とし、フィードを先頭から再取得する。

履歴等の取得失敗は既存の新着順相当のフォールバックへ戻す。AIを同期で呼び出さず、AI停止時は未分類として通常の推薦を継続する。表示履歴の保存失敗は閲覧を妨げない。

## 今回の範囲と確認

公平性の調整は新着から取得した候補群の中で行う。全投稿への均等配信や古い投稿の初回表示を保証しない。表示人数が少ない順は候補群をまたいだ全体順位でもない。読み方の選択・テーマ休止・同一テーマ内の状況理解は後続の設計対象とし、今回の3枠へ推測で組み込まない。

自動テストでは、身近から未知への順序、未分類・属性未回答の扱い、閲覧者数と新しさの優先度、重複閲覧・投稿者自身・先読みの除外、ページ境界、候補不足、フォールバックを確認する。利用者による「無理なく読める」「異なる声に出会えた」の評価や実運用の分布評価は別途必要。
