# 目安箱 デザイン指針

## 目的

目安箱は、知らない誰かの悩みに出会い、自分の悩みもそっと置いていける場所である。画面はSNSや管理画面のように情報を並べるのではなく、**絵本の1ページを静かに開く体験**として設計する。

この文書は、画面の追加・実装・レビュー時に参照する共通の判断基準である。機能や状態の詳細は [画面詳細設計](./screens/README.md) を参照する。

## デザインコンセプト

### 絵本のような親しみやすさ

- 子ども向けに限定せず、どの世代にも親しみやすい、やわらかな手づくり感を作る。
- 画面の主役は投稿本文と利用者の行動であり、装飾は読書を邪魔しない量に抑える。
- 「評価する」「競う」雰囲気を作らない。リアクション、クイズ、履歴は、他者の声に出会ったことを表す。

### クレヨンと紙

- 見出し、短い操作名、しおりなどに、少し揺らいだ手書き・クレヨン風の表現を使う。
- 本文と入力欄は読みやすい標準的な日本語書体を使う。長文を手書き書体にしない。
- 各画面の背景は温かい白い紙に約5mm間隔の淡い方眼を敷き、コンテンツは白い紙片・しおりとして表現する。紙片の面には方眼を重ねない。
- 角丸は完全に均一にせず、わずかに不揃いにする。輪郭は細く、影はクレヨンで添えた程度に留める。
- 下部ナビゲーションは、本文の紙に貼り込んだ一枚の紙片として扱う。本文との境界は細い直線で区切り、操作の並びを安定させる。
- 貼り込む紙片の色は、本文の紙よりわずかに濃い温かい白に留める。中央の「投稿」は他の項目と同じ高さに置き、淡い紫の背景で控えめに示す。
- 星、雲、月などの小さな落書きは、画面ごとに一つまでとする。意味を持たせず、操作対象にも使わない。
- 例外として、フィードの表紙だけは絵本の表紙として扱い、太陽・雲・チューリップを一枚の絵として置く。本文を載せる紙には持ち込まない。絵は線と塗りの二層で描き、塗りを輪郭からわずかにずらして、クレヨンで塗ったはみ出しを残す。
- もう一つの例外として、起動画面には主題をクレヨン1本とし、シールを3枚まで置く。起動画面は「この本の題字を書いている時間」であり、絵は待たせていることの代わりではなく、書いている手そのものを表す。ここで本を開かない。ノートを開く動作はフィードの表紙が持っており、起動画面でも開くと同じ所作が二度続いて表紙の見せ場がなくなる。
- 絵の揺らぎは、絵の大きさに合うものを選ぶ。紙いっぱいの絵の揺らぎを小さな絵にかけると、周期が絵の中を何度も横切り、手の震えではなく形のうねりになる。クレヨンのように平行な2辺を持つ形では、この違いがそのまま「別の物に見える」ことになる。

### 動き

動きは、操作の結果か、画面の意味を伝えるときだけに使う。待たせていることを埋めるために動かさない。

- 紙をめくる、色が入る、シールが貼られるなど、紙とクレヨンの世界で実際に起きることだけを動かす。回転、点滅、視差、弾むカードは使わない。
- 動き出しから終わりまでを1秒前後に収め、終わったあとは静止するか、ごくわずかな息づかいだけを残す。
- 起動画面のように待ち時間が読めない画面では、描き切るまでの時間を最低表示時間として保証し、準備が先に終わった場合は残りを早送りして収める。描いている途中で画面を切り替えない。
- `prefers-reduced-motion: reduce` では、動きを省いた完成形をそのまま出す。動きでしか伝えていない情報を作らない。

## 情報量と画面遷移

### 基本原則

- 1画面に見せる主要な行動は一つだけにする。
- 初期表示で、見出し、主コンテンツ、主要操作が画面内に収まることを基準にする。
- 情報をカード、バッジ、グラフで細分化しない。主役以外の情報は、折りたたみ・設定画面・次の画面へ退避する。
- 同時に複数の投稿、複数のクイズ設問、複数の集計を見せない。
- スクロールは基本的に使わない。フィードは紙をめくる操作で1件ずつ進む。クイズは1通ずつ進む。

### スクロールを許容する例外

次の場合だけ、下部ナビより上の本文領域の縦スクロールを許容する。横スクロール、無限スクロール、カード内スクロールは使わない。

- 投稿詳細の本文が画面高を超える場合
- 投稿フォームで、文字サイズの拡大やキーボード表示により入力欄・補助項目が画面高を超える場合
- エラーや安全上の注意を省略せず表示する必要がある場合
- フィード、クイズ、履歴を含む各画面で、画面高の不足または文字拡大により、必須情報・操作を省略せず表示するために必要な場合

この場合も、主要操作は内容の直後に置き、操作ボタン自体の固定表示や不必要な重複を避ける。

## 画面共通の見た目

| 要素 | 指針 |
| --- | --- |
| レイアウト | 360px以上のスマホ向け1カラム。左右16〜24pxを基準にし、PC向けのレイアウトは設計しない。 |
| 背景 | 温かい白の紙に淡い5mm方眼を敷く。強いグラデーション、写真背景、装飾的なテクスチャの多用はしない。 |
| 色 | 主操作は落ち着いた紫を基本にし、黄色・ミント・桃色はしおりや紙片の補助色として控えめに使う。意味や状態を色だけで伝えない。 |
| 文字 | 本文は16px以上を目安にする。手書き書体は見出し・短いラベル・ボタンに限定し、本文・注記・入力内容では可読性を優先する。 |
| 操作 | タップ領域は44px以上を目安にする。押せる要素には言葉を添え、絵や装飾だけを操作にしない。 |
| 余白 | 情報を減らした代わりに余白を残す。要素を詰めて「かわいさ」を作らない。 |

### 文字サイズと密度

- 文字サイズの設定は、投稿本文、フォーム、主要操作、下部ナビゲーション、画面内の状態表示へ反映する。
- 通常表示でも、下部ナビゲーションのラベルは小さな注記のように扱わない。本文・状態見出しとの階層差を保ちつつ、読み取れる大きさと48px以上のタップ領域を確保する。
- 文字サイズは viewport や端末の文字設定に依存しない固定値で定義し、標準・大きく表示の切り替えはアプリ内の表示設定だけで行う。文字サイズを変更したときは、情報を縮めたり重ねたりせず、必要な空間を確保する。
- 文字が大きいときは、情報を縮めたり重ねたりせず、1列への切り替えや通常スクロールで必要な空間を確保する。
- 操作の補助ラベルだけを一段小さくし、選択中の値、入力値、ボタンの文言は同じ操作階層として揃えた大きさにする。

## 共通コンポーネント

### 紙片

投稿本文、投稿入力欄、次の推薦は、少し不揃いな角丸の紙片として扱う。1画面に紙片を重ねすぎず、最も大切な内容だけを紙片に載せる。

### しおり

テーマ、クイズの参加者、履歴は、短い文字を載せたしおりで表現する。しおりの色は補助的な装飾であり、テーマや正誤を色だけで区別しない。

### リアクション

リアクションの名称は **「そっと寄りそう」** に統一する。返信、いいね、評価ではなく、「読んで受け取った」ことを表す一種類の操作とする。選択済み状態は、文言・件数・押下状態を組み合わせて示す。

### 表示設定

文字サイズ、原文・ひらがな・英語、読み上げは下部ナビから開く設定画面にまとめる。本文の近くに常時多くの切替を並べない。

設定画面は、項目を詰めた一覧ではなく、ひとつずつ選べる紙面として扱う。見出し、説明、選択肢、次の項目の間に十分な余白を置き、直線の罫線ではなく、既存の輪郭と同じクレヨン風の細い線で区切る。区切り線は項目の終了位置に置き、設定タイトルの直後にも線を置く。最後の項目の後には線を置かない。

## 画面ごとの適用

| 画面 | 主役 | 見せ方 |
| --- | --- | --- |
| フィード | 1件の投稿本文 | 1枚の紙片を読み、紙の角・スワイプ・左右キーで進む。投稿者情報は公開された年代・都道府県など最小限にする。 |
| 投稿 | 本文入力 | 大きな1枚の紙に書く。音声入力は「話して書く」とし、任意属性は折りたたむ。 |
| 投稿詳細 | 投稿本文 | 本文を最優先し、「そっと寄りそう」は本文の後に置く。表示設定は下部ナビから設定画面を開く。 |
| クイズ | 1通の投稿 | 3人をしおり、投稿を手紙として扱う。1通ずつ対応を選び、正誤より言葉を読む体験を優先する。 |
| 履歴 | 出会ったテーマ・都道府県 | 数字のダッシュボードではなく、読んだ声のしおりを並べる。集計とクイズ履歴は必要な分だけ開ける。 |

## アクセシビリティと安全性

- 手書き・クレヨン表現は装飾であり、本文の可読性、コントラスト、フォーカス表示を損なわない。
- ブラウザやOSの文字拡大時に、情報を隠したり横スクロールを発生させたりしない。
- 選択、送信、エラー、読み込み、リアクションの結果は、色以外に文言と操作状態で伝える。
- 匿名性と安全に関わる説明は、装飾的な言い換えだけにせず、短く明確な言葉で表示する。
- 送信中は重複操作を防ぎ、投稿・クイズの入力内容は通信失敗時にも保持する。
- 色味はこの指針の世界観を保ったまま、[デジタル庁デザインシステムのアクセシビリティ指針](https://design.digital.go.jp/dads/foundations/color/accessibility/)を参照する。本文・ラベル・アイコンは背景とのコントラスト比を4.5:1以上、操作要素の輪郭など文字以外の情報は3:1以上とし、キーボード操作時のフォーカス位置を常に見分けられるようにする。

## 避けること

- SNSのような無限フィード、複数投稿の密な一覧、通知バッジ、ランキング
- ダッシュボード型のカード群、過剰な数値・グラフ・フィルター
- 大きなキャラクター、画面を覆うイラスト、過剰なアニメーション
- 全文への手書き書体の適用、低コントラストな薄い文字
- 絵本風の装飾を理由に、必要な安全説明・エラー・操作名を曖昧にすること
